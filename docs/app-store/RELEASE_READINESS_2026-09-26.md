## Apple release gates

1. Run the [build 23 physical TestFlight script](WHAT_TO_TEST_1.0.0_23.md) with authorized student and staff accounts. Confirm production sign-in, role boundaries, messaging, uploads, voice draft, push, recordings, deletion request, and cold-start/offline behavior. Record failures and fixes before calling the build accepted.
2. Recheck the current App Store Connect version, attached build, support/privacy URLs, age-rating answers, export-compliance answer, app privacy labels, and reviewer access. The screenshots in this repo were produced from development-only fictional data before the September feature additions; compare them with the final binary and replace any screen that no longer represents it.
3. Exercise user-generated-content controls against production: terms acceptance, objectionable-content filtering, report and response, block, and published support contact. Apple's [Guideline 1.2](https://developer.apple.com/app-store/review/guidelines/#user-generated-content) requires these for apps with messaging.
4. Reconcile third-party processors, analytics, optional microphone/audio, selected media, diagnostics, and account deletion with the privacy policy and App Store privacy labels. Apple's [Guideline 5.1.1](https://developer.apple.com/app-store/review/guidelines/#privacy) requires an accessible privacy policy and an in-app deletion path where accounts can be created. The current in-app path and public request page are implemented; completion of requests remains an operational responsibility.
5. Explain invitation-only access and supply a stable reviewer account. Review the Google sign-in flow against [Guideline 4.8](https://developer.apple.com/app-store/review/guidelines/#login-services). Its exception for education apps requiring an existing education account may apply, but this should be checked against the actual CSG account model and documented for App Review rather than assumed.
6. Review whether any digital lesson or service is bought or unlocked in the app or by a link from it. The current release documents no in-app sale; if monetization changes, reassess [Guideline 3.1.1](https://developer.apple.com/app-store/review/guidelines/#in-app-purchase) before submission.
7. Attach the accepted build to the public version and [submit for App Review](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-app/) only after the above evidence is current. TestFlight availability alone does not submit the public version.

Check this if EAS APKs will continue to be distributed directly. [Android developer verification](https://developer.android.com/developer-verification/guides).
