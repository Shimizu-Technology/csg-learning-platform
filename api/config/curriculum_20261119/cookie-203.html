Authentication answers who is making a request. In this course Rails stores the signed-in user ID in an encrypted session cookie. A password digest verifies the password without storing the password itself.

Read the CSG Rails session and CSRF guide. Start from your working API on a feature branch. Add bcrypt and has_secure_password, migrate password_digest, and create a demo user. Confirm a valid password authenticates, an invalid one fails, and serializers never expose password_digest.

Follow the guide's Rails API middleware/session-store setup, including request-forgery protection. Use an HTTP-only cookie, SameSite=Lax and Secure in production. CORS does not replace CSRF protection. Restart Rails after changing the middleware or Gemfile.

Submit: push the API repo and include the PR URL plus valid/invalid password results in Notes, with no credentials or digests. Done when hashing works and the API is ready for session-based signup/login. The older class recording discusses JWTs; it is optional historical context, not the implementation for this curriculum.
