Temporary login until lesson 228

Your Rails task endpoints must stay protected and scoped to the current user. The React login form arrives in lesson 228. Until then, borrow a token from your own local API through the HTTPie desktop app. Never turn authorization off to make React work.

  1. Start Rails with rails server. In HTTPie, open a login tab: POST http://localhost:3000/api/v1/login. Add your demo user's email and password as name/value rows in Params, then click Send. Copy the jwt value from the successful response.
  2. Open your local React site and its DevTools Console. Type localStorage.setItem("token", "PASTE_YOUR_LOCAL_DEMO_JWT_HERE"), replacing the placeholder privately. This is a temporary local demo token. Never commit it or include it in a submission or screenshot.
  3. After importing api from ./lib/api in App.jsx, before rendering the app, add the following temporary setup. Reload the page.
const token = localStorage.getItem("token");
if (token) {
  api.defaults.headers.common["Authorization"] = `Bearer ${token}`;
} else {
  delete api.defaults.headers.common["Authorization"];
}

Use one Axios base URL, import.meta.env.VITE_API_BASE_URL, configured in .env.local as VITE_API_BASE_URL=http://localhost:3000/api/v1. Restart Vite after changing it. Requests then use paths such as /tasks, without another /api/v1.

Check the Network tab: the request should include a Bearer Authorization header and return only your user's data. A 401 means check the token, its expiry, and the header. Log in again through HTTPie if needed. For lesson 226, repeat with a second demo user's token for the empty-list/data-separation check, and an invalid token for the 401 check. Reload after each change and restore your valid demo token afterward.

In lesson 228, remove this temporary block and clear the borrowed token. The real login and shared AuthContext will own token storage and headers.
