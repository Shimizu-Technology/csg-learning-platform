One same-origin session client

This curriculum uses Rails cookie sessions, not Bearer JWTs. Follow the matching Rails session guide and React session guide. Keep the session cookie HTTP-only and first-party, with SameSite=Lax and Secure in production. Do not put a session cookie, password or CSRF token in localStorage.

Use one Axios instance from src/lib/api.js, with baseURL: import.meta.env.VITE_API_BASE_URL || "/api/v1" and an Accept: application/json header. Set VITE_API_BASE_URL=/api/v1. In development, configure Vite server.proxy to send /api requests to http://localhost:3000. Same-origin requests carry the session cookie automatically. The browser calls the frontend origin; Vite forwards the API request without stripping /api. Restart Vite after changing its config or environment.

In HTTPie desktop, login/signup/password changes use Body → Form → URL-encoded name/value rows, never Params or the URL. Params are for non-sensitive query values. Keep CSRF secrets in the X-CSRF-Token header and the session in the cookie jar. Use the guide's shared refreshCsrfToken, setCsrfToken and writeRequest helpers. Fetch GET /csrf, keep csrf_token in memory, and send X-CSRF-Token on POST, PATCH/PUT and DELETE. Use the new token returned after signup/login; clear it after logout and fetch a fresh one. Reads use api.get; writes use writeRequest on that same instance. Never disable CSRF to clear a 422.

Log in through your React form before protected reads or writes. A 401 means the session is missing or expired; show login. A CSRF 422 means check the fresh token and matching cookie; keep the form usable, fetch a fresh token and let the user retry. Read the response body before deciding which error happened. No borrowed token or Authorization header is used.
