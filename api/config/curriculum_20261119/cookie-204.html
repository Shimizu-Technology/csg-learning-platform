Build signup with the CSG Rails session guide. Generate the namespaced users and CSRF controllers first. Implement GET /api/v1/csrf and POST /api/v1/users, permit the intended signup fields and return useful validation errors. Never accept an admin role or expose password_digest.

In the HTTPie desktop app keep the cookie jar enabled. Use localhost consistently (do not switch between localhost and 127.0.0.1). GET /api/v1/csrf and copy csrf_token to the X-CSRF-Token Headers row for signup. Use Body → Form → URL-encoded name/value rows with user[name], user[email], user[password] and user[password_confirmation]. Never put passwords or other secrets in Params or the URL. Keep the response cookie between requests.

On successful signup, reset the old session, set session[:user_id], and return safe user data plus a fresh CSRF token. Test valid signup (201), duplicate/invalid signup (422), and a missing-CSRF write (422). Copy the fresh CSRF token after a successful signup before the next write.

Commit and push. Submit the API repo URL and safe request/status results in Notes. Done when a user can sign up, the cookie jar holds the new session, invalid data is explained and CSRF remains enabled. The older token-based recording is optional context.
