Deploy the Rails API to Render and the React frontend to Netlify. The older recording explains the pieces; use this checklist and the maintained CSG deployment guide for the current settings.

  1. Pass your local backend acceptance checklist and push the API repository. Use the API's own repository, separate from the frontend.
  2. Create Render PostgreSQL and a Ruby web service in Singapore. Configure production to read DATABASE_URL, using the database's internal URL in the same region. Keep credentials in Render environment variables.
  3. Add executable bin/render-build.sh in the API repo. For an API-only app it installs gems and runs migrations:
#!/usr/bin/env bash
set -o errexit
bundle install
bundle exec rails db:migrate

Run chmod +x bin/render-build.sh, commit and push it. Set Render's Build Command to ./bin/render-build.sh and Start Command to bundle exec rails server -b 0.0.0.0 -p $PORT. Set RAILS_ENV=production, DATABASE_URL and RAILS_MASTER_KEY privately. Follow the Render Rails 8 guide for any settings specific to your app; API-only apps have no asset-precompile step.

Do not put db:create or db:seed in the dashboard build command. Render provisions the database. Prefer creating demo users and data through your deployed API; run an explicitly reviewed, repeat-safe seed separately only if needed. Free web services have no SSH shell.

Deploy, read the build log, and check /up returns 200. In HTTPie desktop, test signup, POST /api/v1/login, and protected CRUD against the HTTPS API. Use Params and the Auth panel. Check missing-token and second-user requests too. Keep secrets out of logs, screenshots, GitHub and submissions.

Free-tier limits: a free Render Postgres database expires 30 days after creation; a workspace can have only one free database. Free web services sleep after 15 idle minutes and may take about a minute to wake. Record your database creation and expiry dates in the README, back up the demo data before expiry, and agree a durable hosting plan with your instructor before relying on the portfolio URL. Do not upgrade or buy a plan as part of this exercise. Current Render free-tier limits.

Submit: your API repository URL and live HTTPS API URL in their separate fields. In Notes paste the /up status and the live login status (201 for the class API), without the response token or credentials. Done when PostgreSQL, health, login and protected CRUD work on the live API and the README records the URLs and expiry plan. Continue with Netlify in lesson 231.
